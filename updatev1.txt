# 🛠️ Project MedTrust 工程级全量重构与实现规范（AI Coding 专用指令书）

## 一、 全局改造目标与架构红线约束（System Constraints）

你现在是一名资深 Go/Python/Vue 全栈架构师与区块链工程师，需要对当前处于单机原型阶段的 `MedTrust` 项目进行标准化工程重构。在编写与修改任何代码时，必须严格遵守以下 **6 条架构红线**：

1. **彻底解耦扁平 Controller，强制落地四层架构**：严禁在 `backend/controller/` 中直接编写文件读写、SQL 查询或复杂权限判断。必须重构为 `Controller（参数校验与响应） -> Service（核心业务逻辑） -> Repository（GORM 数据持久化） -> Pkg（加密/IPFS/Fabric/风险引擎基础设施）` 的四层结构。


2. **消灭明文落盘，强制执行 AES-256-GCM + AAD 认证加密**：严禁将未加密的明文医疗文件直接写入 `ipfs_storage/`。所有上传文件必须先计算原始明文的 `SHA-256` 摘要（`file_hash`），再使用 `AES-256-GCM` 算法（将 `patient_id` 与 `record_no` 组合注入 `AAD` 附加认证数据防重放）生成密文后存入 IPFS。


3. **双模驱动设计（Live 真实容器 + Mock 本地降级）**：`IPFSService` 与 `BlockchainService` 必须定义为 Go `interface` 接口，并在 `config.yaml` 中通过 `mode: "live" | "mock"` 控制实现类切换。`live` 模式通过 Fabric Gateway gRPC 与 Kubo HTTP API 连接真实 Docker 容器；`mock` 模式平滑降级为操作本地 `backend/data/fabric_ledger/ledger_history.json` 与 `backend/data/ipfs_storage/`，确保开发环境与答辩演示零崩溃。


4. **单一安全守门人（Single Gatekeeper）**：所有跨机构病历调阅请求必须收口至 `service/access_engine.go`，严格按顺序执行：**Step 1: RBAC 角色过滤 $\rightarrow$ Step 2: ABAC 属性匹配 $\rightarrow$ Step 3: 患者显式授权核验 $\rightarrow$ Step 4: RiskEngine 动态风险评分**，或走 **Break-Glass 临床急救通道**。


5. **AI Agent 零数据库直连原则**：`ai_agent/`（Python FastAPI）严禁引入 `pymysql`、`sqlalchemy` 等任何数据库驱动，也严禁直接读取本地存储目录。`tools.py` 中的所有工具函数必须强制接收调用者的 `jwt_token`，以 HTTP Client 身份携带 `Authorization: Bearer <token>` 请求头回调 Go 后端的 `/api/v1/*` 受控接口。


6. **锁定角色与模块边界**：系统严格固定为 4 类角色（`doctor` 医生、`patient` 患者、`admin` 管理员、`supervisor` 监管人员）与 7 大功能模块，文件仅支持 `pdf/jpg/png`，AI 仅做自然语言检索与审计分析，不开发自动诊断或开药功能。

## 四、 核心算法与底层基础设施实现规范（含完整代码逻辑）

### 算法 1：链上链下协同加密存储算法（`backend/pkg/crypto/aes_gcm.go`）

* **数学与密码学原理**：
1. 原始医疗文件记为 $\text{PlainData}$，计算原始明文哈希：$H_{\text{raw}} = \text{SHA-256}(\text{PlainData})$。


2. 随机生成 32 字节（256 位）数据加密密钥 $K_{\text{DEK}}$ 与 12 字节（96 位）随机初始化向量 $IV$。


3. 构造附加认证数据 $\text{AAD} = \text{fmt.Sprintf}("patient:\%d\vert{}record:\%s", \text{patientID}, \text{recordNo})$，防止攻击者在 IPFS 上将患者 A 的密文文件偷换挂载到患者 B 的病历下。


4. 执行认证加密：$(C, T) = \text{AES-256-GCM-Encrypt}(K_{\text{DEK}}, IV, \text{PlainData}, \text{AAD})$，输出包含 16 字节 AuthTag 的密文流存入 IPFS。


5. 使用系统配置的 32 字节主密钥 $K_{\text{Master}}$ 将 $K_{\text{DEK}}$ 加密后存入 `medical_files.encrypted_dek`。



```go
package crypto

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"encoding/hex"
	"errors"
	"fmt"
	"io"
)

// ComputeSHA256 计算字节流 SHA-256 十六进制哈希
func ComputeSHA256(data []byte) string {
	sum := sha256.Sum256(data)
	return hex.EncodeToString(sum[:])
}

// BuildAAD 构造绑定患者ID与病历编号的附加认证数据 (防密文替换重放攻击)
func BuildAAD(patientID uint64, recordNo string) []byte {
	return []byte(fmt.Sprintf("patient:%d|record:%s", patientID, recordNo))
}

// EncryptMedicalFile 生成随机 256-bit DEK 与 96-bit IV，执行带 AAD 的 AES-256-GCM 加密
func EncryptMedicalFile(plainData []byte, patientID uint64, recordNo string, masterKey []byte) (cipherData []byte, encryptedDEK string, ivBase64 string, fileHash string, err error) {
	if len(masterKey) != 32 {
		return nil, "", "", "", errors.New("masterKey must be 32 bytes for AES-256")
	}
	// 1. 计算原始明文 SHA-256
	fileHash = ComputeSHA256(plainData)

	// 2. 生成 32 字节随机 DEK 与 12 字节随机 Nonce (IV)
	dek := make([]byte, 32)
	if _, err = io.ReadFull(rand.Reader, dek); err != nil {
		return
	}
	iv := make([]byte, 12)
	if _, err = io.ReadFull(rand.Reader, iv); err != nil {
		return
	}

	// 3. 使用 DEK + IV + AAD 加密明文病历
	block, err := aes.NewCipher(dek)
	if err != nil {
		return
	}
	aesGCM, err := cipher.NewGCM(block)
	if err != nil {
		return
	}
	aad := BuildAAD(patientID, recordNo)
	cipherData = aesGCM.Seal(nil, iv, plainData, aad)

	// 4. 使用 MasterKey 加密保護 DEK (信封加密)
	masterBlock, err := aes.NewCipher(masterKey)
	if err != nil {
		return
	}
	masterGCM, err := cipher.NewGCM(masterBlock)
	if err != nil {
		return
	}
	dekNonce := make([]byte, 12)
	if _, err = io.ReadFull(rand.Reader, dekNonce); err != nil {
		return
	}
	sealedDEK := masterGCM.Seal(dekNonce, dekNonce, dek, nil) // 前12字节存dekNonce

	encryptedDEK = base64.StdEncoding.EncodeToString(sealedDEK)
	ivBase64 = base64.StdEncoding.EncodeToString(iv)
	return cipherData, encryptedDEK, ivBase64, fileHash, nil
}

// DecryptMedicalFile 解封 DEK 并校验 AAD 与 AuthTag，还原病历明文
func DecryptMedicalFile(cipherData []byte, encryptedDEK string, ivBase64 string, patientID uint64, recordNo string, masterKey []byte) ([]byte, error) {
	sealedDEK, err := base64.StdEncoding.DecodeString(encryptedDEK)
	if err != nil || len(sealedDEK) < 12 {
		return nil, errors.New("invalid encrypted DEK")
	}
	iv, err := base64.StdEncoding.DecodeString(ivBase64)
	if err != nil {
		return nil, errors.New("invalid IV nonce")
	}

	// 1. 解封 DEK
	masterBlock, err := aes.NewCipher(masterKey)
	if err != nil {
		return nil, err
	}
	masterGCM, err := cipher.NewGCM(masterBlock)
	if err != nil {
		return nil, err
	}
	dekNonce := sealedDEK[:12]
	dek, err := masterGCM.Open(nil, dekNonce, sealedDEK[12:], nil)
	if err != nil {
		return nil, errors.New("failed to unseal DEK: " + err.Error())
	}

	// 2. 使用 DEK + IV + AAD 解密密文并验证 GCM AuthTag
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	aesGCM, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	aad := BuildAAD(patientID, recordNo)
	plainData, err := aesGCM.Open(nil, iv, cipherData, aad)
	if err != nil {
		return nil, errors.New("ciphertext authentication failed (possible tampering or AAD mismatch)")
	}
	return plainData, nil
}

```

### 算法 2：动态完整性验证比对算法（`backend/service/medical_service.go`）

当调用 `POST /api/v1/verification/{record_id}` 时，严格执行以下 5 步比对算法：

1. 根据 `record_id` 查询 MySQL 获取 `medical_records` 与 `medical_files`（提取 `record_no`、`patient_id`、`ipfs_cid`、`encrypted_dek`、`iv_nonce` 及数据库保存的 `db_hash`）。


2. 调用 `BlockchainService.QueryMedicalAsset(record_no)` 从 Hyperledger Fabric 账本获取不可篡改的原始存证对象 `chainAsset`（提取 $H_{\text{chain}} = \text{chainAsset.FileHash}$ 与 $CID_{\text{chain}} = \text{chainAsset.CID}$）。


3. 调用 `IPFSService.Cat(ipfs_cid)` 从链下节点拉取当前密文流 `cipherBytes`。


4. 调用 `crypto.DecryptMedicalFile` 尝试解密还原 $\text{PlainData}'$：


* 若 GCM 认证解密报错（说明 IPFS 密文被破坏或替换），直接判定为 `TAMPERED`（已被篡改）；


* 若解密成功，计算当前明文哈希 $H_{\text{calc}} = \text{ComputeSHA256}(\text{PlainData}')$。




5. 执行三重一致性比对：

$$\text{IsIntact} = (H_{\text{calc}} == H_{\text{chain}}) \land (H_{\text{db}} == H_{\text{chain}}) \land (CID_{\text{db}} == CID_{\text{chain}})$$


* 若 `IsIntact == true`，更新 `medical_records.integrity_status = "VERIFIED"`，记入审计日志并返回绿色通过状态；


* 若 `IsIntact == false`，更新 `medical_records.integrity_status = "TAMPERED"`，写入 `HIGH` 级高危审计告警日志，返回篡改详情（同时展示 `calc_hash`、`db_hash` 与 `chain_hash` 供前端弹窗对比）。

### 算法 3：三层复合访问控制与动态风险评分引擎（`backend/pkg/risk/engine.go` & `service/access_engine.go`）

#### 3.1 动态风险评分算法（白盒加权规则引擎 `pkg/risk/engine.go`）

为保证答辩时算法 100% 可解释，采用四维特征加权求和模型，总分限制在 $[0, 100]$ 区间：


$$S_{\text{total}} = \min\left(100, \; S_{\text{time}} + S_{\text{cross}} + S_{\text{freq}} + S_{\text{batch}} + S_{\text{history}}\right)$$

各维度计分规则如下：

1. **访问时段风险 $S_{\text{time}}$（满分 25 分）**：
* 常规工作时间（08:00 ~ 18:00）：$+0$ 分；


* 夜间延长门诊时段（18:00 ~ 22:00 或 06:00 ~ 08:00）：$+10$ 分；
* 凌晨高危非工作时段（22:00 ~ 次日 06:00）：$+25$ 分。




2. **跨机构与科室属性风险 $S_{\text{cross}}$（满分 25 分）**：
* 本院同科室调阅：$+0$ 分；
* 本院跨科室调阅：$+10$ 分；
* 跨医院同专业科室调阅：$+15$ 分；


* 跨医院且跨专业科室调阅（如骨科医生调阅外院精神科/妇产科病历）：$+25$ 分。




3. **短时高频访问风险 $S_{\text{freq}}$（满分 25 分）**：
* 统计该医生过去 10 分钟内的访问请求次数 $N_{10\text{m}}$（通过 Redis 滑动窗口或 SQL 聚合查询）：


* $N_{10\text{m}} \le 5$ 次：$+0$ 分；


* $6 \le N_{10\text{m}} \le 15$ 次：$+15$ 分；
* $N_{10\text{m}} > 15$ 次（疑似爬虫或批量拖库）：$+25$ 分。




4. **单日跨患者广度与历史异常风险 $S_{\text{batch}} + S_{\text{history}}$（满分 25 分）**：
* 统计该医生过去 1 小时内访问的不同患者数量 $P_{1\text{h}}$：$P_{1\text{h}} > 10$ 人则 $+15$ 分，否则 $+0$ 分；


* 查询该医生过去 7 天内是否存在被拦截（`INTERCEPTED`）或违规紧急访问（`CLOSED_VIOLATION`）记录：存在则 $+15$ 分。





**风险等级与决策映射规则**：

* **低风险（`LOW`，$0 \le S_{\text{total}} \le 30$）**：决策为 `ALLOWED`（若已具备患者有效授权，直接自动放行并返回解密凭证）。


* **中风险（`MEDIUM`，$31 \le S_{\text{total}} \le 70$）**：决策为 `PENDING_CONFIRM`（触发动态步进认证，挂起请求并向患者端推送二次确认通知，待患者点击允许后放行）。


* **高风险（`HIGH`，$S_{\text{total}} > 70$）**：决策为 `REJECTED`（一票否决直接阻断访问，并在 `audit_logs` 中生成高危告警）。



```go
package risk

import (
	"encoding/json"
	"time"
)

type RiskContext struct {
	RequestTime        time.Time
	DoctorHospitalID   uint64
	TargetHospitalID   uint64
	DoctorDeptName     string
	TargetDeptName     string
	Recent10mCount     int64 // 近10分钟该医生访问次数
	Recent1hPatients   int64 // 近1小时该医生访问不同患者数
	Recent7dViolations int64 // 近7天该医生被拦截或违规次数
}

type RiskEvaluation struct {
	TotalScore int               `json:"total_score"`
	RiskLevel  string            `json:"risk_level"` // LOW, MEDIUM, HIGH
	Decision   string            `json:"decision"`   // ALLOWED, PENDING_CONFIRM, REJECTED
	Breakdown  map[string]int    `json:"breakdown"`
	Reasons    []string          `json:"reasons"`
}

func EvaluateAccessRisk(ctx RiskContext) *RiskEvaluation {
	breakdown := make(map[string]int)
	var reasons []string
	total := 0

	// 1. 时间段评估
	hour := ctx.RequestTime.Hour()
	if hour >= 22 || hour < 6 {
		breakdown["time_risk"] = 25
		total += 25
		reasons = append(reasons, "凌晨非工作时段(22:00-06:00)敏感调阅(+25)")
	} else if (hour >= 18 && hour < 22) || (hour >= 6 && hour < 8) {
		breakdown["time_risk"] = 10
		total += 10
		reasons = append(reasons, "夜间非标准门诊时段调阅(+10)")
	} else {
		breakdown["time_risk"] = 0
	}

	// 2. 跨机构与科室属性评估
	if ctx.DoctorHospitalID != ctx.TargetHospitalID {
		if ctx.DoctorDeptName != "" && ctx.TargetDeptName != "" && ctx.DoctorDeptName != ctx.TargetDeptName {
			breakdown["cross_org_dept_risk"] = 25
			total += 25
			reasons = append(reasons, "跨医疗机构且跨专业科室调阅(+25)")
		} else {
			breakdown["cross_org_dept_risk"] = 15
			total += 15
			reasons = append(reasons, "跨医疗机构同科协同调阅(+15)")
		}
	} else if ctx.DoctorDeptName != ctx.TargetDeptName {
		breakdown["cross_org_dept_risk"] = 10
		total += 10
		reasons = append(reasons, "院内跨科室调阅(+10)")
	}

	// 3. 短时访问频率评估
	if ctx.Recent10mCount > 15 {
		breakdown["frequency_risk"] = 25
		total += 25
		reasons = append(reasons, "近10分钟高频访问超过15次(+25)")
	} else if ctx.Recent10mCount >= 6 {
		breakdown["frequency_risk"] = 15
		total += 15
		reasons = append(reasons, "近10分钟访问频次偏高(+15)")
	}

	// 4. 批量患者广度与历史违规评估
	if ctx.Recent1hPatients > 10 {
		breakdown["batch_patient_risk"] = 15
		total += 15
		reasons = append(reasons, "近1小时调阅超过10名不同患者(+15)")
	}
	if ctx.Recent7dViolations > 0 {
		breakdown["history_anomaly_risk"] = 15
		total += 15
		reasons = append(reasons, "近7天存在异常拦截或违规记录(+15)")
	}

	if total > 100 {
		total = 100
	}

	eval := &RiskEvaluation{
		TotalScore: total,
		Breakdown:  breakdown,
		Reasons:    reasons,
	}
	if total <= 30 {
		eval.RiskLevel = "LOW"
		eval.Decision = "ALLOWED"
	} else if total <= 70 {
		eval.RiskLevel = "MEDIUM"
		eval.Decision = "PENDING_CONFIRM"
	} else {
		eval.RiskLevel = "HIGH"
		eval.Decision = "REJECTED"
	}
	return eval
}

func (e *RiskEvaluation) ToJSON() string {
	b, _ := json.Marshal(e)
	return string(b)
}

```

#### 3.2 三层复合访问控制决策流水线（`backend/service/access_engine.go`）

当医生请求调阅/下载某份病历 `record_id` 时，`AccessEngine.CheckAndRecordAccess()` 严格按以下顺序判断：

* **第 1 层（RBAC 角色与账号状态过滤）**：检查操作者角色是否为 `doctor`（或患者本人 `patient_id == user.id`）。若医生 `user.status == "DISABLED"` 直接拒绝；若为跨院请求且 `user.status == "RESTRICTED"`，直接拦截并提示“账号处于跨院访问受限处罚期”。


* **第 2 层（ABAC 属性过滤）**：校验医生所属机构 `Hospital.Status == 1`，校验医生职称 `Title` 不为空。若病历属于本院且同科室创建医生本人，直接放行；若为跨机构调阅，进入第 3 层。


* **第 3 层（患者显式授权核验）**：查询 `authorizations` 表，检查是否存在满足以下全部条件的记录：


1. `patient_id == record.PatientID` 且 `status == "ACTIVE"`；


2. 当前时间 `NOW() BETWEEN start_time AND end_time`；


3. `(auth_target_type == "DOCTOR" AND auth_target_id == doctor.ID)` 或 `(auth_target_type == "HOSPITAL" AND auth_target_id == doctor.HospitalID)`；


4. `scope_type == "ALL"` 或 `(scope_type == "SINGLE" AND record_id == record.ID)`。




* 若不存在有效授权，直接拒绝常规访问（返回 HTTP 403，前端引导急诊医生点击“Break-Glass 紧急访问通道”）。




* **第 4 层（动态风险评分决策）**：调用 `risk.EvaluateAccessRisk(ctx)` 计算得分，将评估结果持久化至 `access_requests` 与 `audit_logs` 表，并按 `ALLOWED / PENDING_CONFIRM / REJECTED` 返回对应响应。

### 算法 4：临床急救“紧急访问（Break-Glass）”状态机与事后追责闭环算法（`backend/service/emergency_service.go`）

针对危重昏迷患者无暇事先授权的临床痛点，构建四阶段状态机闭环：

1. **阶段 1（医生端触发破窗调阅 `POST /api/v1/access/break-glass`）**：
* 校验医生 `status == "NORMAL"`，校验必填项 `emergency_reason` $\in \{\text{RESCUE}, \text{COMA}, \text{CRITICAL}\}$、临床抢救说明 `description` 长度 $\ge 15$ 字符，且 `doctor_confirmed == 1`。


* 生成紧急事件单号 `event_no`（如 `EA20261013001`），初始状态设为 `patient_feedback = "PENDING"`、`audit_status = "PENDING_AUDIT"`。


* **强制上链备案**：调用 `BlockchainService.CreateEmergencyRecord()` 将事件写入 Fabric 不可篡改账本，获取 `fabric_tx_id`。


* **临时放行解密**：立即为医生返回该病历的临时解密视图，同时在 `audit_logs` 写入 `operation_type = "BREAK_GLASS"`、`risk_level = "HIGH"` 的强审计记录。




2. **阶段 2（患者端事后知情与异议申诉 `POST /api/v1/emergency-events/{event_no}/feedback`）**：
* 患者登录系统后，收到弹窗/消息提醒，查看是谁、在什么时间、以什么抢救理由调阅了自己的哪份病历。


* 患者可提交 `feedback = "CONFIRMED"`（确认急诊属实无异议）或 `feedback = "OBJECTED"`（认为属于非急诊违规窥探，发起投诉并附 `patient_comment`）。




3. **阶段 3（监管端独立裁决与自动惩戒 `POST /api/v1/supervisor/emergency-events/{event_no}/audit`）**：
* 监管人员查看紧急事件单、链上存证凭证与患者反馈意见，提交裁决结果 `decision`：


* 若 `decision == "CLOSED_APPROVED"`（合规结案）：更新数据库与 Fabric 链上状态为 `CLOSED_APPROVED`；


* 若 `decision == "CLOSED_VIOLATION"`（确认违规）：更新数据库与 Fabric 链上状态为 `CLOSED_VIOLATION`，**同时自动触发联动惩戒**：将该医生账号 `users.status` 更新为 `"RESTRICTED"`（剥夺其后续跨院调阅与发起紧急访问的权限），并写入链上审计记录。

2. **标准受控工具函数定义（`ai_agent/tools.py`）**：
只允许通过 `httpx` 或 `requests` 调用 Go 后端的 REST API，并完整返回后端的权限拦截信息（如 403 未获患者授权）及调用链路轨迹 `tool_trace`：



```python
import requests
from typing import Dict, Any

GO_BACKEND_URL = "http://localhost:8088/api/v1"

class ControlledMedicalTools:
    def __init__(self, bearer_token: str):
        self.headers = {
            "Authorization": bearer_token if bearer_token.startswith("Bearer ") else f"Bearer {bearer_token}",
            "Content-Type": "application/json"
        }
        self.trace_logs = []

    def query_patient_records(self, patient_id: int = 0, data_type: str = "") -> Dict[str, Any]:
        """受控工具1：查询当前登录用户有权查看的医疗记录列表"""
        params = {}
        if patient_id > 0:
            params["patient_id"] = patient_id
        if data_type:
            params["data_type"] = data_type
        resp = requests.get(f"{GO_BACKEND_URL}/medical-records", headers=self.headers, params=params, timeout=10)
        result = resp.json()
        self.trace_logs.append({
            "tool": "query_patient_records",
            "endpoint": "GET /api/v1/medical-records",
            "status_code": resp.status_code,
            "auth_check": "PASSED" if resp.status_code == 200 else "INTERCEPTED_BY_GATEKEEPER"
        })
        return result

    def query_my_authorizations(self, status: str = "") -> Dict[str, Any]:
        """受控工具2：查询患者授权策略状态列表"""
        params = {"status": status} if status else {}
        resp = requests.get(f"{GO_BACKEND_URL}/authorizations", headers=self.headers, params=params, timeout=10)
        result = resp.json()
        self.trace_logs.append({
            "tool": "query_my_authorizations",
            "endpoint": "GET /api/v1/authorizations",
            "status_code": resp.status_code,
            "auth_check": "PASSED" if resp.status_code == 200 else "INTERCEPTED_BY_GATEKEEPER"
        })
        return result

    def verify_record_integrity(self, record_id: int) -> Dict[str, Any]:
        """受控工具3：触发指定病历的 IPFS 链下密文与 Fabric 链上存证 Hash 动态完整性核验"""
        resp = requests.post(f"{GO_BACKEND_URL}/verification/{record_id}", headers=self.headers, timeout=10)
        result = resp.json()
        self.trace_logs.append({
            "tool": "verify_record_integrity",
            "endpoint": f"POST /api/v1/verification/{record_id}",
            "status_code": resp.status_code,
            "auth_check": "PASSED" if resp.status_code == 200 else "INTERCEPTED_BY_GATEKEEPER"
        })
        return result

    def analyze_audit_anomalies(self, risk_level: str = "HIGH") -> Dict[str, Any]:
        """受控工具4：检索访问审计日志与异常高风险行为记录（仅监管员/患者本人可用）"""
        resp = requests.get(f"{GO_BACKEND_URL}/audit-logs", headers=self.headers, params={"risk_level": risk_level}, timeout=10)
        result = resp.json()
        self.trace_logs.append({
            "tool": "analyze_audit_anomalies",
            "endpoint": "GET /api/v1/audit-logs",
            "status_code": resp.status_code,
            "auth_check": "PASSED" if resp.status_code == 200 else "INTERCEPTED_BY_GATEKEEPER"
        })
        return result
```
